# Foreground Refinement Technology Spike (docs/13_FOREGROUND_REFINEMENT_TECHNOLOGY_SPIKE.md)

This spike evaluates methods for converting coarse binary foreground subject-segmentation masks into clean, smooth, high-quality boundaries with soft transition alpha values and canonical trimaps.

> [!IMPORTANT]
> **Largely superseded (2026-08-04). Retained as a historical record.** The
> morphological reconstruction and guided-filter pipeline this spike specifies
> is now skipped entirely when a portrait matting backend is in use, because
> that backend already resolves the boundary and re-refining it destroyed
> detail it had produced (DEC-033). The refinement path still runs for the
> coarse MediaPipe segmenter, which is diagnostic-only.
>
> Edge decontamination survives and is still used, though its reach was
> recalibrated (DEC-030).

## 1. Problem Statement

Coarse masks generated by segmentation models (such as MediaPipe Selfie Segmenter) suffer from:
1. **Ragged boundaries**: Blocky, jagged pixel steps because of thresholding.
2. **Internal holes**: Noisy pixels inside the subject region.
3. **Isolated noise**: Spurious foreground pixels in the background.
4. **No antialiasing/trimap**: Downstream replacement needs alpha values and trimap bands (0/128/255) for smooth blending.

## 2. Evaluated Approaches

| Approach | Pros | Cons | Decision |
|---|---|---|---|
| **Deterministic NumPy Morphology** | Pure Python/NumPy, zero new dependencies, highly auditable, fully deterministic. | Slightly slower than C implementations. | **Selected (Baseline)** |
| **Scipy ndimage Morphology** | Faster compiled C operations. | Introduces compiled C dependencies, deployment risk. | Deferred |
| **Scikit-Image Morphology** | Rich morphological functions. | Heavy transitive dependencies (`scipy`, compiled packages). | Deferred |
| **Pymatting / Alpha Matting** | High quality soft boundaries. | GPL license risks, heavy native dependencies. | Deferred |
| **MODNet / ONNX-based Matting** | Deep learning quality. | Large model files (~80MB), ONNX Runtime dependency. | Deferred |

## 3. Selected Architecture: Morphological Refiner

To ensure absolute determinism, zero new dependencies, and CPU-friendly execution, we use a custom NumPy morphological refiner:
1. **Closing (Dilation then Erosion)**: Fills small internal holes in the coarse mask.
2. **Opening (Erosion then Dilation)**: Removes thin protrusions, tendrils, and isolated noise.
3. **Shift-based implementation**: Avoids FFT convolution boundary/wraparound artifacts by performing explicit NumPy-shifted logical operations.
4. **Face protection**: Restores face/head region coordinates from erosion using face detection bounding boxes.
5. **Alpha/Trimap generation**: Combines the morphological results with original model probability values inside the uncertainty boundary band (dilation XOR erosion).

Refer to DEC-015 in `docs/08_DECISION_LOG.md` for the official decision record.
